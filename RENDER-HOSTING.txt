HelpCentre Pro — easy Render hosting (ebubeprimex)
==================================================

GOAL
----
- Code lives on GitHub account: ebubeprimex
- Every git push to GitHub auto-deploys on Render
- API + Tenant app + Admin app + Postgres from one Blueprint
- Admin and tenant use DIFFERENT public URLs


STEP 1 — Create the GitHub repo (once)
--------------------------------------
1. Sign in as: ebubeprimex
2. Create a new repository named: Help_Center_Pro_webapp
   (private is fine)
3. Leave it EMPTY (no README / .gitignore / license)


STEP 2 — Push this project to ebubeprimex (once)
------------------------------------------------
Open PowerShell in this folder and run:

  git remote add ebubeprimex https://github.com/ebubeprimex/Help_Center_Pro_webapp.git
  git push -u ebubeprimex master

If GitHub asks you to sign in, use the ebubeprimex account.


STEP 3 — Deploy on Render (once, ~5 minutes)
--------------------------------------------
1. Go to: https://dashboard.render.com
2. Sign in with GitHub → authorize ebubeprimex
3. Click: New +  →  Blueprint
4. Select repo: ebubeprimex/Help_Center_Pro_webapp
5. Render reads render.yaml and creates:
     - helpcentre-pro-db       (Postgres)
     - helpcentre-pro-api      (API Gateway — public /api/v1)
     - helpcentre-pro-auth     (Auth service)
     - helpcentre-pro-tenant   (Tenant / admin API)
     - helpcentre-pro-identity (Users, roles, invitations)
     - helpcentre-pro-tickets  (Tickets + realtime)
     - helpcentre-pro-notify   (Email / notifications)
     - helpcentre-pro-web      (Tenant / workspace app)
     - helpcentre-pro-admin    (Platform Admin Portal — separate URL)

   If you already have a Blueprint: push render.yaml, then click Manual sync
   and approve the new services. Copy RESEND_API_KEY / EMAIL_FROM onto
   auth, identity, tickets, and notify (sync: false secrets).
6. Blueprint already sets API URL + CORS for the known onrender hosts.
   Still set email secrets on helpcentre-pro-api before Apply:

     RESEND_API_KEY = (same re_... value as local backend .env)
     RESEND_WEBHOOK_SECRET = (same whsec_... value as local backend .env)
     EMAIL_FROM = HelpCentre Pro <noreply@helpcentrepro.com>
     SUPPORT_EMAIL_FROM = HelpCentre Pro Support <support@helpcentrepro.com>

   If your service URLs differ from helpcentre-pro-*.onrender.com, update
   FRONTEND_URL, ADMIN_FRONTEND_URL, CORS_ORIGINS, and VITE_* to match,
   then Manual Deploy the static sites (Vite bakes VITE_* at build time).

7. Click Apply


STEP 4 — After first deploy
---------------------------
API health:     https://helpcentre-pro-api.onrender.com/health
Swagger:        https://helpcentre-pro-api.onrender.com/api-docs

Tenant login:   https://helpcentre-pro-web.onrender.com/login
Admin login:    https://helpcentre-pro-admin.onrender.com/login

Security: the tenant host never links to or redirects into Admin.
  /admin/* on the tenant app shows a restricted-access screen and does not
  reveal the Admin Portal URL. Public admin account creation is disabled —
  admins are seeded / managed inside the platform. Admin APIs reject tenant
  tokens and (in production) browser calls that do not originate from the
  Admin host.

Default platform super admin (seeded on API start):

  Password: 2020/EN/12566

After sign-in, change password from the Admin sidebar lock icon. Changed
credentials are preserved across restarts.


EVERYDAY WORKFLOW
-----------------
1. Change code locally
2. git add .
3. git commit -m "your message"
4. git push ebubeprimex master
   (or git push origin master if dual-push is configured)

Render auto-deploys from the GitHub push. No manual upload.


NOTES
-----
- Free Render services sleep after idle time; first request may take ~30–60s.
- Vite env vars are baked at build time — set them before the first build,
  or Manual Deploy after changing VITE_* values.
- Locally (combined portal): tenant login is /login, admin login is /admin/login.
